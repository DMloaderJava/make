## 3. P0 — блокеры, исправлять первыми

### P0-1. Критические уязвимости в зависимостях

```
next  16.0.0 - 16.4.0   critical   (RCE в Image Optimization при SVG, cache poisoning SSG/ISR,
                                    SSRF в Image Optimization, DoS через Server Actions)
zod   < 4.6.6            high       (исчерпание памяти на больших коллекциях)
source-map-js 1.0.0-1.2.1 high
```

Версия запинена точно (`"next": "16.3.7"`), поэтому `npm audit fix` без `--force` не сработает. Исправленные версии уже есть в реестре: `next@16.4.3`, `zod@4.6.7`.

**Что менять:**

```jsonc
// package.json
"next": "16.4.3",              // было 16.3.7
"eslint-config-next": "16.4.3", // держать в локстепе с next
"zod": "^4.6.7",
```

Затем `npm install` и полный `npm run verify`. Часть advisories касается фич, которые проект не использует (`next/image`, `use cache`), но RCE в image optimizer и cache poisoning — не тот случай, когда стоит полагаться на «мы это не вызываем».

### P0-2. SSRF на серверном прокси

`/api/llm` и `/api/seo` принимают `baseUrl` из тела запроса, а `resolveLLMProxyUrl()` для провайдера `custom` возвращает его без проверки:

```ts
// src/app/api/llm/route.ts:101
const target = resolveLLMProxyUrl(providerId, { baseUrl, accountId });
// ...
const res = await fetch(`${target}/chat/completions`, { ... });
```

Любой, кто прошёл парольную форму (или попал на инстанс без `MVS_PASSWORD`), может заставить сервер стучаться во внутреннюю сеть: `http://169.254.169.254/…`, `http://localhost:PORT/…`, сервисы в приватной сети — и получить ответ обратно (тело ошибки отдаётся клиенту).

**Что менять** — один guard, общий для обоих маршрутов:

```ts
// src/lib/providers/proxyGuard.ts
const BLOCKED = [/^127\./, /^10\./, /^192\.168\./, /^169\.254\./, /^172\.(1[6-9]|2\d|3[01])\./, /^\[?::1\]?$/];

export function assertProxyTarget(raw: string): URL {
  const url = new URL(raw);                       // бросит на мусоре
  if (url.protocol !== 'https:') throw new Error('proxy: only https allowed');
  const host = url.hostname;
  if (host === 'localhost' || host.endsWith('.local') || BLOCKED.some(r => r.test(host))) {
    throw new Error('proxy: private targets are not allowed');
  }
  return url;
}
```

Плюс `signal: AbortSignal.timeout(60_000)` на каждый серверный `fetch`: сейчас в `src/app/api/*` нет ни одного `AbortSignal`, поэтому зависший апстрим держит воркер до платформенного таймаута (`maxDuration = 60`).

### P0-3. Автосейв теряет данные при ошибке записи

```ts
// src/components/studio/editor/useEditorPersistence.ts:27-37, 69
const handleSave = async () => {
  if (!project) return;
  setSaveStatus('saving');
  const saved = await saveProject(snapshot, { allowStale: true }); // ← может бросить QuotaExceededError
  ...
  setSaveStatus('saved');
};
// ...
setTimeout(() => { handleSave(); }, 2000);   // ← без .catch
```

Если квота переполнена (сценарий L-3 из `known-limits.md` — импорт больших WAV), `saveProject` бросает исключение: пользователь не видит ничего, статус навсегда остаётся «Сохраняю…», в консоли — unhandled rejection. Через 24 часа проект удалится по TTL. Для браузерного редактора, где IDB — единственное хранилище, это потеря работы.

**Что менять:**

```ts
const handleSave = async () => {
  if (!project) return;
  setSaveStatus('saving');
  try {
    const saved = await saveProject(snapshot, { allowStale: true });
    setProject(p => (p ? { ...p, revision: saved.revision } : p)); // без мутации
    setSaveStatus('saved');
    scheduleCloudSync(saved);                                      // см. P1-1
  } catch (e) {
    setSaveStatus('error');
    const quota = e instanceof DOMException && e.name === 'QuotaExceededError';
    toast(quota
      ? 'Не удалось сохранить: закончилось место. Освободите хранилище (Настройки → Хранилище).'
      : `Не удалось сохранить: ${(e as Error).message}`, 'error');
  }
};
// в эффекте: setTimeout(() => { void handleSave(); }, 2000)
```

Статус `'error'` надо добавить в тип и в индикатор в шапке редактора.

### P0-4. Ревизии/мультитаб фактически не защищены

`allowStale: true` на каждом сохранении отключает ровно ту проверку, ради которой существует `StaleProjectRevisionError` (`db.ts:20-32`). Две вкладки с одним проектом перезаписывают друг друга без предупреждения — а редактор открывается долго, и вторая вкладка/окно Electron — типичный сценарий.

**Что менять:** сохранять с `expectedRevision`, ловить `StaleProjectRevisionError` и предлагать «перезагрузить данные» / «сохранить поверх». Минимум — не передавать `allowStale` и показывать баннер «Проект изменён в другой вкладке».

## 4. P1 — важно, делать в ближайшие 1–2 итерации

### P1-1. Облачная синхронизация: нет выключателя и она слишком частая
`syncProjectSnapshot(saved)` вызывается на **каждом** автосейве (debounce 2 с), т.е. при обычном наборе текста это запросы каждые 2 секунды. Хуже: `POST /api/cloud/project` перед записью выполняет `cleanupExpired()` — ещё один DELETE к Supabase (`route.ts:62`). Итог: два внешних запроса каждые 2 секунды на одну открытую вкладку.

Плюс это вопрос приватности: в `deployment guide` Supabase позиционируется как «временные снапшоты», но пользователь не выбирает, отправлять их или нет; сценарий и реплики уходят на сервер всегда.

**Что менять:** (1) тумблер `cloudSyncEnabled` в `AppSettings` (по умолчанию выкл. для self-host, вкл. для Vercel-деплоя); (2) отдельный троттлинг: не чаще 1 раза в 60 с или только по явному `Ctrl+S`; (3) показывать в настройках время последней облачной копии.

### P1-2. Удаление проекта не чистит облако
`deleteProjectSnapshot()` экспортируется, но не вызывается ни разу. Пользователь удаляет проект → локальные данные стёрты → снапшот с диалогами живёт в Supabase до истечения TTL (24 ч). Достаточно одного вызова в `page.tsx` рядом с `deleteProject(id)`.

### P1-3. Нет `navigator.storage.persist()`
Хранилище помечается как «best-effort». Под давлением квоты браузер вправе вытеснить OPFS/IDB — данные исчезнут не по TTL, а по решению браузера, без предупреждения. Вызов идемпотентный и бесплатный:

```ts
// при создании проекта / первом сохранении
if (navigator.storage?.persist && !(await navigator.storage.persisted())) {
  await navigator.storage.persist(); // в Chromium выдаётся автоматически при установке/активности
}
```
Статус `persisted` стоит показывать в «Настройки → Хранилище» (`info.ts` уже собирает `usage/quota`).

### P1-4. API-маршруты не валидируют вход
Все семь маршрутов делают `const { providerId, text, apiKey } = await req.json()` и дальше используют значения как есть. При этом `zod` уже в зависимостях и в `validators.ts` есть схемы для vision/SEO.

**Что менять:** по схеме на маршрут, ограничения `text.max(5000)`, `providerId` — `z.enum` из реестра, `apiKey.max(4096)`. Это одновременно и защита от мусорных 500-к, и читаемые 400-е:

```ts
const TTSSchema = z.object({
  providerId: z.string().max(64),
  text: z.string().min(1).max(5000),
  apiKey: z.string().min(1).max(4096),
  voice: z.string().max(128).optional(),
  language: z.string().max(16).optional(),
  speed: z.number().min(0.25).max(4).optional(),
  model: z.string().max(128).optional(),
});
```

### P1-5. Аутентификация: минимальный, но нужный апгрейд
Сейчас: `MVS_PASSWORD` → cookie со значением `sha256("mvs:"+пароль)` без срока жизни кроме `maxAge`, без ротации, без rate-limit на форму, плюс сохранённый для совместимости `GET /?password=…` (утечка в логи прокси и `Referer`).

Минимум:
- счётчик неудачных попыток на IP (in-memory, 5 попыток / 15 мин) — уже сильно снижает риск перебора;
- удалить `?password=` (или включать флагом `MVS_ALLOW_URL_PASSWORD=1`);
- `MVS_SECURE_COOKIE` по умолчанию определять от `x-forwarded-proto`, а не от переменной;
- задокументировать, что при пустом `MVS_PASSWORD` приложение **полностью открыто**, и печатать предупреждение в лог на старте.

### P1-6. `.env.example` противоречит коду
`src/proxy.ts:30-33` пишет «по умолчанию Secure выключен, потому что типовой self-host по http», а `.env.example` и `DEPLOYMENT_GUIDE_RU.md:62` ставят `MVS_SECURE_COOKIE=1`. **Уточнено при перепроверке:** на `http://localhost` Chromium/Firefox считают origin доверенным и Secure-cookie сохраняют, поэтому локальный запуск работает. Ломается доступ по **обычному http на не-localhost** (`http://192.168.1.5:3000`, self-host по IP/домену без TLS): браузер такой cookie не сохраняет → **бесконечный цикл логина**. Оставить в `.env.example` закомментированную строку с пояснением «включайте только за HTTPS».

### P1-7. Безопасность заголовков
`next.config.ts` не задаёт ни CSP, ни `X-Frame-Options`, ни `Referrer-Policy`, ни `Permissions-Policy`; `X-Powered-By` остаётся. Для self-host, куда ходят с ключами в localStorage, CSP — не роскошь (XSS = кража всех ключей).

```ts
async headers() {
  return [{
    source: '/(.*)',
    headers: [
      { key: 'X-Frame-Options', value: 'SAMEORIGIN' },
      { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
      { key: 'X-Content-Type-Options', value: 'nosniff' },
      { key: 'Permissions-Policy', value: 'camera=(), microphone=(), geolocation=()' },
      { key: 'Content-Security-Policy', value: CSP },
    ],
  }];
},
poweredByHeader: false,
```

CSP начинать в `report-only`, иначе сломаются inline-стили Tailwind-классов и blob-URL для аудио.

### P1-8. Текст в UI про ключи не соответствует поведению
`ProviderList.tsx:301`: «Все ключи хранятся только в браузере (localStorage). **Сервер их не видит.** Прокси через /api/* только для CORS». Это верно только для direct-провайдеров. Все провайдеры с `cors: 'proxy'` (ElevenLabs, Azure, PlayHT и др.) отправляют ключ в теле POST на наш `/api/tts`, где сервер подставляет его в исходящий запрос. Ключ не логируется и не пишется в БД — но «сервер не видит» неправда.

**Что менять:** «Ключи direct-провайдеров не покидают браузер; для провайдеров, заблокированных по CORS, ключ передаётся вашему серверу по HTTPS и используется только для запроса к API провайдера». Заодно стоит подписать: «localStorage доступен любому скрипту на этом origin — не ставьте сторонние расширения».

### P1-9. Три источника истины для TTS-синтеза
`api/tts/route.ts` (312 строк): 10 явных `case` (elevenlabs, openai, gemini, polly, azure, google-cloud, cartesia, deepgram, qwen + группа playht/resemble/murf/fish/hume/speechify) → общий fallback через `getServerGenerate` → `default` с подсказкой. Часть провайдеров описана и там, и в `providers/tts/*.ts`.

**Что менять:** оставить один путь — `switch` только для трёх настоящих исключений (Gemini PCM→WAV, Polly с опциональным SDK, Azure SSML), всё остальное через `getServerGenerate`. Тест `ttsProviderPolicy.test.ts` уже следит за политикой — расширить его на «все реализованные провайдеры достижимы через `/api/tts`».

### P1-10. `any` и обработка ошибок
164 предупреждения, из них 122 `no-explicit-any` (плюс 11 `react-hooks/exhaustive-deps` и 11 `set-state-in-effect`); `catch (e: any)` в 20 местах, `e.message` отдаётся клиенту как есть (может содержать внутренние URL, лимиты аккаунта, фрагменты ключа в эхе запроса).

**Что менять:** (1) `catch (e: unknown)` + общий `toErrorMessage(e)`; (2) в API-маршрутах — маппинг через уже существующие `mapTTSProviderError` / `mapLLMProviderError` + отдельный `code` для клиента; (3) снять baseline по файлу, по одному правилу (`no-explicit-any`) — сейчас он «warn» и потому не виден в PR.

## 5. P2 — техдолг и упущенная функциональность

### P2-1. Экспорт упирается в память
`new BufferTarget()` (`videoEncoder.ts:255`) держит готовый MP4 целиком в heap: 10 минут 1080p при 5 Мбит/с ≈ 375 МБ, час ≈ 2,2 ГБ → вкладка падает. mediabunny умеет `StreamTarget`/`FileSystemWritableFileStream`.

**Что менять:** при доступном File System Access API (`showSaveFilePicker`) писать сразу в файл: `StreamTarget` → WriteStream → диск. Fallback — текущий `BufferTarget`. Это же снимает пик памяти перед скачиванием.

### P2-2. Нет выбора формата вывода
Зашито `width: 1920, height: 1080, fps: 30` (`useEditorExport.ts:187-189`), битрейт 5 Мбит/с (`videoEncoder.ts:85,269`). Превью рисуется в 1280×720 и пропорционально масштабируется, так что технически поддержка других разрешений уже есть — нужен только UI и передача параметров.

Практическая ценность высокая: **вертикаль 1080×1920** для Shorts/Reels — сегодня основной формат для озвучки манги; 720p нужен для длинных роликов и слабых машин. Добавить в `ExportModal`: пресеты `1920×1080`, `1080×1920`, `1280×720`, `3840×2160`, `fps 24/30/60`, «качество (битрейт)».

### P2-3. Изображения держатся как dataURL
`getProjectWithImages()` → `loadProjectImageAsDataURL()` → массив base64-строк в состоянии редактора. Для 100 страниц по 2 МБ это ~270 МБ JS-строк (base64 +33 % + копии при конкатенации) — заметно даже в Chromium.

**Что менять:** отдавать `Blob`/`File` из OPFS и создавать `URL.createObjectURL` (реестр `objectUrlRegistry.ts` уже есть и умеет дедупликацию и `revokeAll`). Освобождение — при размонтировании редактора.

### P2-4. Фоновая музыка — половина фичи

Это «мёртвая настройка», которая вводит в заблуждение. Либо доделать (в roadmap v1.5), либо убрать поля до реализации.

- Firefox/Safari/iOS: в CI только Chromium, `smoke:editor` — только Linux.
- Две вкладки на одном проекте: проверка ревизий отключена.
- Проекты длиннее 15 минут: память `OfflineAudioContext` (L-2) и экспорт в RAM.
- Реальные ключи всех 15 TTS и 13 LLM: `smoke:tts` требует ключей и в CI не идёт.
- Любые UI-клики: компонентных тестов нет, только два браузерных smoke.

**Короткий вывод.** Инженерное ядро (сценарий → таймлайн → SRT → камера → NLE → локальное
хранилище) — это то, что действительно работает и покрыто осмысленными тестами; оно и раньше
не было проблемой. Реальные риски сосредоточены в трёх местах: **браузерный экспорт под нагрузкой,
автосейв при переполнении квоты и серверные прокси-маршруты**. Именно туда стоит вкладываться,
а не в проверки согласованности документации.

### 13.2. Что пришлось поправить в самом аудите

1. **Кнопки без `type`:** было «23 однострочных», по факту **43 из 100** — первая оценка считала только `<button …>` в одну строку и пропускала многострочные теги.
2. **`MVS_SECURE_COOKIE=1` в `.env.example`:** формулировка «бесконечный цикл логина при локальном запуске» неверна. На `http://localhost` Chromium и Firefox считают origin доверенным и Secure-cookie сохраняют. Ломается доступ по **http на не-localhost** (LAN-IP, self-host по домену без TLS). Правка в §P1-6 внесена.
3. **Тесты, читающие исходники:** было «11 файлов», после чистки осталось **2** (`desktopConfig` читает `package.json`/`.gitignore`, `editorControllerContract` разбирает AST) — оба про контракт, а не про поиск подстроки.

Разбивка: 122 `no-explicit-any`, 11 `react-hooks/exhaustive-deps`, 11 `set-state-in-effect`, 6 `no-require-imports`, по 3 `immutability`/`prefer-const`, по 2 `no-img-element`/`empty-object-type`.
